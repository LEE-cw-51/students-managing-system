# 공통 틀 컴팩트화

## Purpose
강사 한 명이 수업 중·후에 학생 관리 화면을 한눈에 더 많이 보고, 덜 스크롤하며 쓰게 한다.

## Primary user
학원 강사 1명. 주로 노트북/데스크톱(1280~1920px), 가끔 휴대폰.

## Core flow (one)
사이드바에서 메뉴 선택 → 페이지 제목/액션 확인 → 본문 카드·표에서 작업 → 필요하면 AI 비서 패널 열기

## Screens in scope
- 공통 틀(사이드바, 위쪽 막대, 페이지 제목 줄, 본문 여백·카드 밀도) — 예시로 "오늘" 화면에 얹어 보여 줌
- 사이드바 접힘(아이콘만) 상태
- 휴대폰 폭

## Out of scope for now
- 각 페이지 내부 구성(오늘·학생·반·보고서의 카드 배치 자체)
- 색·글꼴 등 스타일 변경

## Style notes
- "컴팩트하게": 여백·글자 크기·카드 안쪽 여백을 한 단계씩 줄인다(스타일 단계에서 처리).

## Assumptions
- 사이드바는 220px → 184px로 줄이고, 접기 버튼으로 56px 아이콘 막대로 바꿀 수 있다. 접힘 상태는 기억한다.
- 학원명/강사명 브랜드 영역은 한 줄로 줄인다. 로그아웃은 사이드바 맨 아래 접기 버튼 옆에 둔다.
- 위쪽 막대 높이를 줄이고(약 48px) 검색·날짜·AI 비서 버튼 배치는 유지한다.
- 페이지 제목 줄: 제목 옆에 부제(날짜 등)를 같은 줄에 두고, 액션 버튼은 같은 줄 오른쪽에 둔다(세로 약 70px → 40px).
- 휴대폰에서는 지금처럼 메뉴 버튼 + 서랍형 사이드바.

## Open questions
- 사이드바 기본값을 펼침으로 할지, 아이콘 막대로 할지
- 위쪽 막대의 날짜를 계속 둘지(오늘 화면 제목 줄에도 날짜가 있어 중복)

# 화면 1: 오늘 / 수업 기록 (v3~)

## Purpose
수업 직후 반 하나의 학생별 기록(출결·점수·집중도·과제·특이사항)을 가장 적은 스크롤로 입력·저장한다.

## Core flow (one)
오늘 보드에서 반 카드 "수업 기록 →" → 학생별 기록 입력(반 공통·지난 숙제는 필요할 때만 펼침) → 저장(Ctrl+S) → 일일 보고서

## Screens in scope
- `today-board`: /today (반 선택 전). 제목 줄(제목·날짜·"오늘로") → 주간 띠(유일한 날짜 이동: ◀ 지난주 / 7일 / 다음 주 ▶ / 날짜 선택) → 수업 카드 → 할 일·D-7 시험·주의 학생·이번 주 숙제 2열
- `lesson-recorder`: /today?class=…. 제목 줄(‹ 오늘 · 반 이름 · 날짜/시간/요일, 이전·다음 수업일 이동) → 비정규일 알림 → 반 공통(접힘 요약) → 학생별 기록 → 지난 숙제 확인(접기 가능) → 오늘 낼 숙제(접힘 요약) → 저장 막대(하단 고정)
- 공통 틀(sidebar, topbar)은 v2 잠금 그대로

## Assumptions
- 별도 머리줄(반 이름·시간)은 제목 줄로 합친다. 수업 기록 화면의 날짜 이동은 "이 반의 이전/다음 수업일"로 바꾼다(하루 단위 ◀▶ 대신).
- 반 공통은 기본 접힘 + 한 줄 요약(진도·테스트·공지). 그 날 기록이 하나도 없으면 펼친 채 시작.
- 과제 등급은 학생별 기록의 과제 칩 한 곳에만 둔다(지난 숙제 표의 "과제 등급" 칸 삭제). 표는 항목별 A–F 입력만.
- 휴대폰: 지난 숙제 표는 학생별 카드로 쌓고, 학생 기록도 한 학생씩 쌓는다. 날짜 이동 버튼은 화살표만, 주간 띠는 건수 대신 점 표시, 저장 막대는 한 줄.
- 저장 안 한 변경이 있을 때 링크 이동도 ConfirmDialog로 묻는다. ↑↓ 키로 학생 줄 이동.
- 보드의 카드 4개 내용·순서는 바꾸지 않는다.

## Open questions
- 학생별 기록을 지난 숙제 확인보다 위에 둘지(현재 안), 숙제 확인 → 학생 기록 순서를 유지할지
- 수업 기록 화면 날짜 이동: 이전/다음 "수업일" 이동이 맞는지, 하루 단위가 필요한지
- 반 공통을 기본 접힘으로 둘지

# 화면 2: 학생 상세 (v4~)

## Purpose
학생 한 명의 상태(다음 수업·출석·숙제·성적·상담)를 한 화면에서 파악하고, 상담 기록 같은 자주 하는 일을 탭 이동 없이 처리한다.

## Core flow (one)
학생 목록/오늘 화면에서 학생 → 개요에서 KPI·특이사항 확인 → 개요의 상담 빠른 기록으로 바로 저장(필요하면 "자세히") → 같은 반 다음 학생으로 이동(Alt+→)

## Screens in scope
- `student-detail` (개요 탭): 제목 줄(‹ 학생 · 이름 · 학년·학교·등록일 · 배지 | 학부모 전화·정보 수정) → 같은 반 이동 막대 → 탭 5개 → KPI 5개 한 줄 → 학교 시험(있을 때만 한 줄) → [상담·후속(빠른 기록 + 후속 할 일 + 최근 상담) | 최근 특이사항] → [반(현재·예정·임시 + 반 변경/배정 + 지난 반 이력 접기) | 기본 정보]
- `student-lessons` (수업·출결 탭): 월 이동 + 범례 → 집계 한 줄(출석률·출석·결석·보강·미입력) → [출결 달력 | 수업 기록 표(줄 끝 [보고서])]. 휴대폰은 달력 아래 수업 카드
- `student-counsel` (상담·보고서 탭): [상담 목록(필터·작성·수정·삭제·후속 완료) | 월간 보고서 목록(복사·펼침)] + 삭제 시 되돌리기 알림만
- 공통 틀과 화면 1(today-board, lesson-recorder)은 v3 그대로

## 탭 정리 (8 → 5)
| 지금 | 새 탭 |
|---|---|
| 개요 | 개요 |
| 출결 | 수업·출결 (달력·집계) |
| 수업 기록 | 수업·출결 (표) |
| 숙제 | 숙제 (그대로) |
| 성적 | 성적 (그대로) |
| 상담 | 상담·보고서 |
| 보고서 · 월간 | 상담·보고서 |
| 보고서 · 일일 | 수업·출결 표의 줄 버튼 [보고서] |
| 반 이력 | 개요 "반" 카드의 "지난 반 이력" 접기 |

옛 `?tab=attendance|lessons|reports|history` 주소는 새 탭으로 연결(리다이렉트)한다.

## Assumptions
- 반 정보는 개요의 "반" 카드 한 곳에만 자세히 둔다. 제목 줄 부제에서 반 이름을 빼고, 같은 반 이동 막대는 반을 선택기로만 보여 준다(반이 하나여도 같은 자리).
- 상담 빠른 기록: 대상(학부모/학생) + 내용 한 칸 + 후속 빠른 설정(1주·2주·한 달) + 저장. 상담일은 오늘, 제목은 비움. "자세히"를 누르면 입력한 내용을 그대로 담아 기존 상담일지 창을 연다.
- 상담 삭제: 확인 창을 없애고 즉시 숨김 + 5초 "되돌리기" 알림만(지금 코드의 지연 삭제 방식 그대로). 후속 할 일 취소 안내는 알림 문구에 넣는다.
- 수업·출결 탭의 기간은 달 단위 하나(1·3·6개월 고르기 제거). 달력 날짜를 누르면 표의 그 날 줄 강조 + 스크롤(별도 상세 카드 제거). 출결 변경은 표의 [출석|결석]에서만.
- 등록일은 제목 줄 메타로 옮기고 기본 정보에서 뺀다.
- 휴대폰: 탭 줄이 넘치면 오른쪽 끝 흐림 + ›, 선택한 탭이 보이게 자동 스크롤. KPI는 2열, 같은 반 막대는 ‹ 학생 선택 › 만. 수업 기록은 카드로 쌓음.
- 숙제·성적 탭 내부 구성은 이번에 바꾸지 않는다(밀도만 공통 틀에 맞춤).

## Open questions
- 월간 보고서를 "상담·보고서" 탭에 둘지, 성적 탭이나 별도 탭으로 둘지
- 수업·출결 탭 기간을 달 단위로만 해도 될지(지금은 최근 1·3·6개월 선택)
- 상담 빠른 기록에서 후속 할 일 이름 없이 저장하면 기본 문구("학부모 후속 연락")로 둬도 될지

# 화면 3: 학생 목록 (v5~)

## Purpose
학생을 빨리 찾아 상세로 들어가고, 여러 학생을 한 번에 반 배정·상태 변경하며, 상담 기록 탭에서 학생 상세에 들어가지 않고 바로 상담을 기록한다.

## Core flow (one)
사이드바 "학생" → 필터 한 줄(검색·학년·반·주의·재원 상태)로 좁힘 → 이름 링크로 학생 상세 / 또는 상담 기록 탭 → 학생 선택 + 빠른 기록 저장

## Screens in scope
- `student-list` (학생 목록 탭): 제목 줄(학생 · 재원 N명 | 학생 등록) → 탭 2개 → 필터 한 줄(검색 고정 폭 · 학년 · 반 · 주의만 · 재원/휴원/퇴원/전체) → 일괄 막대(선택했을 때만, 위 고정) → 학생 표. 휴대폰은 학생 카드
- `student-counsel-list` (상담 기록 탭): 제목 줄(학생 · 부제, 등록 버튼 없음) → 탭 2개 → 상담 빠른 기록(학생 선택 + 대상 + 내용 + 후속 빠른 설정 + 자세히/저장) → 필터 한 줄(기간 + 30일·90일 · 대상 · 검색) → 상담 표. 휴대폰은 상담 카드
- 공통 틀과 화면 1·2(today-board, lesson-recorder, student-detail, student-lessons, student-counsel)는 v4 그대로

## Assumptions
- 이동 대상은 이름 링크 하나. 표 줄 전체 클릭(onClick)은 없앤다. 체크칸·전화 링크와 겹치지 않고 키보드·화면 낭독기에 링크가 하나만 잡힌다. 줄 hover 배경은 유지.
- "학생 등록"은 학생 목록 탭에서만 보인다. 긴 부제는 빼고 재원 인원만 제목 옆에 둔다.
- 필터: 검색창 220px 고정, 학년·반은 짧은 선택 상자, 상태는 오른쪽 끝 segmented. 휴대폰은 검색 한 줄 + 나머지는 줄바꿈.
- 상담 빠른 기록은 학생 상세 개요의 빠른 기록(CounselingTab의 NoteForm 재사용, "자세히" → 기존 상담일지 창)과 같은 모양에 학생 선택만 앞에 붙인다. 상담일은 오늘, 제목은 비움. 저장하면 목록을 다시 불러온다.
- 상담 기록 목록은 보기 + 새로 쓰기만. 수정·삭제는 학생 상세 상담·보고서 탭에서.
- 상담 기간 필터는 기간 버튼 + 30일·90일 빠른 선택(기본 90일, 지금과 같음).
- 휴대폰(≤640px): 학생·상담 모두 한 건 = 카드 한 장. 체크칸·이름 링크·전화 버튼은 42px 이상.
- 일괄 막대(반 배정·상태 변경)의 기능은 그대로, 휴대폰에서는 두 줄로 줄바꿈.

## Open questions
- 상담 빠른 기록을 상담 기록 탭 맨 위에 늘 펼쳐 둘지, "상담 쓰기" 버튼으로 열지
- 상담 기록 목록에서도 수정·삭제를 할 수 있어야 할지
- 학생 표의 "학부모 연락처" 칸을 데스크톱에서도 유지할지(휴대폰 카드에는 전화 버튼으로 둠)

# 화면 4: 반 상세 (v6~)

## Purpose
반 하나의 상태(다음 수업·출석·숙제·테스트·진도)를 파악하고, 수업 계획과 실제 기록을 한 탭에서 날짜별로 맞춰 보며 고친다.

## Core flow (one)
반 목록/오늘 화면에서 반 → 개요에서 KPI·최근 수업·계획 확인 → "수업 계획·기록" 탭에서 날짜 줄의 [계획](앞으로 할 일) 또는 [기록 →](그 날짜 수업 기록 화면) → 저장 후 돌아옴

## Screens in scope
- `class-detail` (개요): 제목 줄(‹ 반 · 반 이름 · 태그 · 시간표·학년·학생 수 | 반 이동 ◀ 선택 ▶ · 수업 기록 · 정보 수정) → 탭 6개 → 시험대비 알림(있을 때) → KPI 5개 → 학교 시험(시험당 한 줄, 있을 때) → [최근 수업 | 강의 계획 + 지금 단원·교재] → 학생 칩
- `class-lessons` (수업 계획·기록 = 진도 기록 + 강의 계획): 월 이동 + AI 초안 만들기 → 초안 검토(있을 때) → 이 달 목표·단원 진행 한 줄(펼침) → 주별 묶음 안에 수업일 한 줄(날짜·상태 | 계획 | 실제 진도·테스트 | 기록 인원 | [계획] [기록 →] [휴강]). 휴대폰은 수업일 카드
- `class-homework` (숙제): 기간(1·3·6개월) + 범례 → 숙제 표(데스크톱, 칸 누르면 항목별 등급, 줄 끝 "확인한 수업 →") / 낸 날별 카드(휴대폰, 못 한 학생만 이름·등급)
- `class-stats` (통계): 6개월 추이 막대 3개 → 표로 보기(데스크톱 표 / 휴대폰 월별 줄) → 학생별 월간 통계(휴대폰 카드)
- 공통 틀과 화면 1~3은 v5 그대로

## 수업 데이터 편집기 (지금 3개 → 2개)
| 지금 | 무엇을 고치나 | 어디서 | 제안 |
|---|---|---|---|
| 수업 기록 화면 `LessonRecorder` (/today?class=…&date=…) | 반 공통(진도·수업 내용·테스트·반 공지), 계획 진행 결과, 학생별 기록, 지난 숙제 등급, 오늘 낼 숙제 | 제목 줄 "수업 기록하기", 오늘 보드 | **유일한 "실제 기록" 편집기**. SessionEditor에만 있던 "메모(보고서 제외)"를 반 공통에 추가 |
| 수업 기록 팝업 `SessionEditor` | 반 공통(진도·수업 내용·테스트·반 공지·메모) — 위와 같은 데이터 | 진도 기록 탭 줄 끝 [수정/입력] | **없앰**. 줄의 [기록 →]이 그 날짜 수업 기록 화면으로 감 |
| 계획 편집 창 `PlanForm` (PlansTab) | 일간 계획(제목·단원·목표·내용·자료·예정 숙제·진행 결과·메모), 월간 목표 | 강의 계획 탭 [작성/수정], 초안 [고치기] | **"앞으로 할 일"만**. 진행 결과 칸은 뺌(수업 기록에서만 고름) |
(관련: 단원 목록 `CurriculumEditor`는 정보 수정 창 안에만 있음 → 이 달 목표 줄의 "단원 진행" 펼침에서도 열 수 있게)

## 삭제·파괴 동작 버튼 (지금)
- 반 삭제(제목 줄): `btn ghost` + 인라인 빨간 글자, 확인 창
- 강의 계획 삭제(PlanForm 아래 왼쪽): `btn ghost`, 빨간색 없음, 확인 창
- 단원 빼기(CurriculumEditor): `btn ghost sm` ✕ 아이콘, 저장된 단원만 확인 창
- 반에서 빼기(학생 탭 일괄 막대): `btn danger sm` 빨간 채움, 확인 창 없음
- 초안 버리기(DraftReview): `btn ghost`, 확인·되돌리기 없음
- 휴강으로 지정(CancelDayDialog 제출): `btn danger` 빨간 채움
- 제안 규칙: 줄·창 안의 삭제 = 빨간 글자 ghost 버튼(한 가지 클래스), 창에서는 아래 왼쪽. 빨간 채움(`btn danger`)은 확인 창/휴강 창의 최종 확정 버튼에만. 되돌릴 수 있는 삭제(계획 삭제·초안 버리기)는 확인 창 대신 5초 되돌리기, 되돌릴 수 없는 반 삭제만 확인 창 유지. 반 삭제는 정보 수정 창 안으로 옮김

## Assumptions
- 진도 기록 탭과 강의 계획 탭을 "수업 계획·기록" 하나로(탭 7 → 6). 기간은 달 단위(1·3·6개월 고르기 제거). 옛 `?tab=progress|plans`는 새 탭으로 연결.
- 숙제 표 안 바로 고치기는 하지 않음: 칸은 항목 평균이라 고칠 대상이 모호하고 넷째 편집기가 생김. 칸 클릭 → 항목별 등급 풀이 상자(터치·키보드 가능), 줄 끝 "확인한 수업 →".
- "확인한 수업" 날짜는 API가 주지 않으면 낸 날 다음 수업일로 계산(`src/` 변경 없이).
- 휴대폰: 숙제 표 → 낸 날별 카드, 6개월 표 → 월별 한 줄, 학생별 월간 통계는 지금 stack-mobile 카드. 탭은 scrollHint.
- 제목 줄 메타에서 교재·담당 강사는 뺌(교재는 개요 "단원·교재", 강사는 한 명). 학교 시험은 표 → 시험당 한 줄.
- 테스트·학생 탭 구성은 그대로(밀도와 삭제 버튼 규칙만).

## Open questions
- 진도 기록 + 강의 계획을 한 탭으로 합칠지, 탭은 두고 편집기만 정리할지
- 진도 기록의 수업 기록 팝업을 없앨지(수업 기록 화면으로 이동), 팝업을 남겨 반 공통만 빨리 고치게 할지
- 반 삭제를 정보 수정 창 안으로 옮길지, 제목 줄에 빨간 글자 버튼으로 남길지

# 화면 5: 반 목록 · 반 등록 (v7~)

## Purpose
반을 빨리 찾아 반 상세로 들어가고, 새 반은 이름과 시간표만으로 바로 등록한 뒤 교재·단원 같은 나머지는 필요할 때 채운다.

## Core flow (one)
사이드바 "반" → 운영 중 목록에서 반 이름 링크 → 반 상세 / 또는 "반 등록" → 반 이름 + 요일·시간 → 등록 → 새 반 상세

## Screens in scope
- `class-list` (/classes): 제목 줄(반 · 운영 N개 · 학생 N명 | 반 등록) → 필터 한 줄(운영 중/종료/전체 + 개수 · 시험대비 휴강만 토글 | 시험대비 반 편성은 시험 탭 →) → 반 표(데스크톱) / 반 카드(휴대폰)
- `class-form` (반 등록 창): 제목 줄(반 등록 · ✕) → 기본·필수(반 이름* · 학년 / 수업 요일·시간*) → ▸ 교재·단원 목록(접힘, 한 줄 요약) → ▸ 기타(접힘: 학년도·학기·담당 강사·메모) → 취소·등록(창 아래 고정)
- `class-form-edit` (반 정보 수정 창, 반 상세 "정보 수정"): 같은 창 + 기본에 상태(운영/종료) · 교재 구획에 교재 기록 · 아래 왼쪽 반 삭제
- 공통 틀과 화면 1~4는 v6 그대로

## 폼 항목 (지금 ClassForm 기준)
| 항목 | 필수 | 구획 |
|---|---|---|
| 반 이름 | 필수 | 기본 |
| 수업 요일 · 시간 (요일 1개 이상, 시작<끝) | 필수 | 기본 |
| 학년 | 선택 | 기본 |
| 상태 운영/종료 (수정만) | 기본값 운영 | 기본 |
| 교재 | 선택 | 교재·단원 |
| 이 교재 시작일 (교재를 새로 넣거나 바꿀 때만) | 조건부 필수 | 교재·단원 |
| 교재 기록 (수정만, 읽기 전용) | - | 교재·단원 |
| 단원 목록 (단원 이름이 있으면 횟수 1~20 필수) | 선택 | 교재·단원 |
| 학년도 (올해로 채워짐) · 학기 · 담당 강사 · 메모 | 선택 | 기타 |

## Assumptions
- 단계식 대신 접는 구획. 필수는 둘뿐이라 기본만 펼쳐 바로 등록하게 하고, 수정할 때는 한 칸만 고치러 오는 경우가 많아 단계 이동이 방해가 된다. 같은 창이 등록·수정 모두에 맞는다.
- 접힌 구획은 한 줄 요약(교재·단원 수·지금 단원 / 학년도·학기·메모 유무). 저장 오류가 접힌 구획에 있으면 그 구획을 펼치고 해당 칸으로 이동. 펼침 상태는 기억하지 않음.
- 둘째 요일부터 "월과 같게"(시간 복사) 편의 버튼 추가 제안.
- 반 삭제는 화면 4 규칙대로 정보 수정 창 아래 왼쪽 빨간 글자 ghost 버튼 + 확인 창. 단원 빼기도 빨간 글자 버튼(저장된 단원만 확인 창).
- 반 목록: 줄 전체 클릭(onClick) 없애고 이름 링크 하나만(학생 목록과 같은 규칙). 긴 부제는 빼고 운영 반 수·학생 수만. 칸 구성은 그대로(반+태그 · 요일·시간 · 학생 · 다음 수업 · 현재 진도 · 교재).
- "시험대비 휴강만" 토글은 목록 데이터(`exam.kind`)로 화면에서 거름(`src/` 변경 없음). 시험대비 반 자체는 지금처럼 시험 탭에서.
- 휴대폰: 반 카드(이름+태그·다음 수업 / 시간표·인원 / 진도·교재), 이름 줄 42px 이상. 등록·수정 창은 화면 전체를 덮고 제목 줄·저장 막대 고정. 요일 버튼 42px, 줄바꿈.
- 반 등록은 지금처럼 목록 위 창(별도 주소 없음), 저장하면 새 반 상세로.

## Open questions
- 폼을 접는 구획으로 할지, 단계식(1 기본 → 2 교재·단원 → 3 기타)으로 할지
- 담당 강사 칸을 기타 구획에 남길지, 등록 폼에서 숨길지(강사 1명)
- 반 목록에 "시험대비 휴강만" 토글을 둘지, 태그 표시만으로 충분한지

# 화면 6: 보고서 (v8~)

## Purpose
수업 뒤 반 하나의 일간 보고서를 빨리 복사해 보내고, 월말에는 여러 학생의 월간 보고서를 한 번에 만들고·확정하고·PDF로 내려받는다.

## Core flow (one)
사이드바 "보고서" → 일간: 날짜·반 고름 → 학생별 복사 또는 "전체 복사" / 월간: 월·반 고름 → 상태로 거름 → 학생 선택 → 생성 → (필요하면 열어서 고침) → 일괄 확정 → 일괄 PDF

## Screens in scope
- `report-daily` (/reports?date=…&class=…): 제목 줄(보고서 · 날짜·반·N명 | 전체 복사 (N명)) → 탭 2개 → 필터 한 줄(◀ 날짜 ▶ · 반 선택 · "이 날 수업한 반" 바로가기, 반을 고른 뒤에도 보임) → 기록 없는 학생 알림(수업 기록하기 →) → 보고서 카드(데스크톱 2열 / 휴대폰 1열, 이름 링크 · 전체 보기 · 복사)
- `report-monthly` (/reports?tab=monthly&month=…&mclass=…): 제목 줄(보고서 · 월·대상·N명) → 탭 2개 → 필터 한 줄(◀ 월 ▶ · 반 | 상태 걸러보기 전체·미작성·임시·확정 + 개수, KPI 카드 4개 대체) → 일괄 막대(선택 시만, 위 고정: 선택 N명·해제 | 기본 생성(n)·AI 생성(n)·임시도 다시 만들기 | 일괄 확정(n)·일괄 PDF(n) + 작업 중 진행 줄·중지) → 표(데스크톱) / 쌓은 줄(휴대폰, 체크칸 "선택"·동작 칸 "보고서" 라벨)
- `report-monthly-editor` (월간 [작성/열기] 창): 제목 줄(이름 N월 보고서 · 상태 · 수업 N회 | ‹ 이전 · 다음 › · ✕) → 다시 만들기 2개 → 본문 → 아래 막대(저장 상태 | 복사 · PDF 저장 · 임시 저장 · 확정)
- 공통 틀과 화면 1~5는 v7 그대로

## 일괄 동작 (src/·lib/ 변경 없이)
| 동작 | 대상(선택 중) | 학생마다 부르는 것 | 방식 |
|---|---|---|---|
| 기본 생성 | 미작성(+체크 시 임시), 수업 1회 이상 | `generateMonthlyReportsBulk` 한 번(지금 그대로) | 서버 한 번 |
| AI 생성 | 같음 | `generateMonthlyAi` → `saveMonthlyReport(임시)` (지금 그대로) | `runLimited` 2명씩 |
| 일괄 확정 | 임시만 | `generateMonthlyReport`(저장 본문 `.text` 읽기) → `saveMonthlyReport({…, report_text, status:'확정'})` | `runLimited` 2명씩, 진행 줄 |
| 일괄 PDF | 임시·확정 | `generateMonthlyReport`(본문) → `downloadMonthlyPdf` (POST `/api/monthly-report/pdf`) | 1명씩 차례로, 학생별 PDF 파일 여러 개 |
- 보드 데이터(`getMonthlyReportBoard`)는 본문을 80자 미리보기만 주므로 확정·PDF 전에 학생마다 본문을 다시 읽어야 한다.
- 하나로 합친 PDF는 불가(지금 기준): `renderMonthlyReportPdf`는 학생 한 명짜리 문서만 만들고, 의존성은 `pdfkit`뿐(합치기·zip 라이브러리 없음). 합치려면 `lib/monthly-pdf.js`에 여러 학생용 함수 + 새 API가 필요 → 이번 범위 밖.
- 크롬은 첫 일괄 PDF 때 "여러 파일 다운로드 허용"을 한 번 묻는다. iOS Safari는 파일마다 미리보기가 떠서 불편 → 휴대폰에서는 일괄 PDF 숨김 제안.

## URL 파라미터
- 일간 반 = `class`(지금 그대로, 시험 기간 화면의 `/reports?tab=daily&class=…` 링크 유지). 월간 반 = `mclass`(새 이름, 빈 값 = 전체 재원생).
- 탭을 바꿔도 두 값은 서로 덮어쓰지 않아 탭마다 마지막 반이 남는다(지금은 일간에서 고른 반이 월간으로 넘어가 월간 선택 상자가 빈 칸이 되거나, 반대로 필터가 걸림).
- 옛 주소: `?tab=monthly&class=X`이고 `mclass`가 없으면 처음 열 때 `mclass=X`로 바꾸고 `class`는 지움(router.replace 한 번).

## Assumptions
- KPI 카드 4개를 상태 걸러보기 버튼 한 줄로 합침(밀도). 거르기는 화면에서만.
- 체크칸은 모든 줄에서 고를 수 있고(지금은 생성 대상만), 동작별 적용 인원을 버튼 괄호에 표시. 0명이면 비활성.
- 일괄 확정은 되돌릴 수 있으므로(같은 본문을 임시로 다시 저장) 확인 창 대신 5초 되돌리기. "임시도 다시 만들기" 생성은 본문을 덮어써 되돌릴 수 없으므로 실행 전 확인 창. 이 화면에 삭제 동작은 없음.
- 진행 중 "중지"는 다음 학생부터 멈춤(지금 AI 생성의 중단 방식과 같음).
- "전체 복사"는 이미 불러온 일간 보고서를 이름순으로 이어 붙임(보고서 사이 빈 줄 + 구분선). 서버 호출 없음.
- 일간 날짜에 ◀▶(하루 이동)을 추가. 이동은 이름 링크 하나(일간 → 학생 상세, 월간 → 학생 상세 상담·보고서 탭).
- 월간 편집 창에 "이전/다음 학생"(지금 표의 거른 순서) 추가, 저장 안 한 변경은 ConfirmDialog.
- 휴대폰: 제목 줄 메타 숨김, 체크칸·버튼 42px 이상, 일괄 막대는 줄바꿈.

## Open questions
- 일괄 PDF를 학생별 파일 여러 개로 내려받기(src/·lib/ 변경 없음) vs 하나로 합친 PDF(lib 변경 필요)
- 일괄 확정을 확인 창 없이 5초 되돌리기로 할지, 확인 창으로 할지
- KPI 카드를 상태 걸러보기 버튼으로 합칠지, 카드를 남길지

# 화면 7: 시험 · 시험대비 기간 (v9~)

## Purpose
학교별 수학 시험 일정을 빠짐없이 채우고, 시험 기간에 학교·학년별 시험대비 반을 편성한 뒤 기간 동안 학생 복귀·휴강 반을 관리한다.

## Core flow (one)
사이드바 "시험" → 학교 시험 일정에서 "아직 일정이 없는 학교" → 한 번에 입력 → 시험대비 기간 탭 → 새 기간 → 편성(① 반 만들기 → ② 학생 넣기 → ③ 휴강 반) → 편성 확정 → 운영 화면에서 복귀일·학생 관리

## Screens in scope
- `exam-schedule` (/exams): 제목 줄(시험 · 학기·시험·일정 수·미입력 수 | 시험 일정 추가) → 탭 2개 → 필터 한 줄(학년도 · 학기 · 시험 종류) → 아직 일정이 없는 학교(표 위로 올림, 0곳이면 숨김: 한 번에 입력 + 학교 칩) → 시험 일정 표(학생 N명 펼침 = 이름 링크) / 휴대폰 학교 카드 → 학교 미입력 재원생 한 줄
- `exam-schedule-bulk` (한 번에 입력 창): 제목 줄(학기 시험 한 번에 입력 · ✕, 고정) → 한 줄 안내 → 데스크톱 표(학교·학년 | 시험일 | 교재 | 범위, Tab=오른쪽·Enter=아래 칸) / 휴대폰 학교 카드(라벨 위 입력칸 세로) → 저장 막대(채운 N곳 | 취소 · N개 저장, 고정)
- `exam-periods` (/exams?tab=periods): 제목 줄(시험 · 진행 중·예정 수 | 새 시험대비 기간) → 탭 2개 → 접는 도움말 한 줄 → 기간 표(이름 링크만, 줄 onClick 없앰) / 휴대폰 기간 카드
- `exam-planner` (/exams/periods/[id], 편성 전 또는 "남은 학생 편성"): 제목 줄(‹ · 기간 이름 · 상태 · 날짜·연결 시험 | 기간 수정) → 구획 이동 줄(위 고정: ① 시험대비 반 N · ② 학생 넣기 · 남은 N명 · ③ 휴강할 원래 반 N) → ① 반 카드(데스크톱 2열, 채운 카드는 접어 한 줄 요약) → ② 검색·넣기 막대(선택 시 위 고정) + 남은 학생 목록(학교·학년 묶음 + 묶음 전체 선택, 높이 제한 없음) → ③ 휴강 반 칩 → 저장 막대(요약 | 편성 확정, 아래 고정)
- `exam-period-op` (/exams/periods/[id], 편성 뒤): 제목 줄(‹ · 기간 이름 · 상태 · 날짜·반·학생 수 | 남은 학생 편성 · 기간 수정 · 기간 마감) → 미편성 알림 → 반 바로가기 줄 → 반 카드(반 링크 · 시간표 · 수업 횟수 | 수업 기록하기 · 일일 보고서 · 학생 추가 → 학생 표 / 휴대폰 학생 카드) → 휴강 반 표
- 공통 틀과 화면 1~6은 v8 그대로

## 안쪽 스크롤 영역 (지금 → 제안)
| 위치 | 지금 | 제안 |
|---|---|---|
| 편성 ② 재원생 표 (`Planner.js`) | `.table-wrap` maxHeight 420 + overflow auto | 높이 제한 없앰, 페이지와 함께 스크롤. 학교·학년 묶음 + 묶음 전체 선택, 검색·넣기 막대를 위 고정 |

| 창 자체 (`.modal`, app.css) | max-height + overflow auto | 유지(창 하나 = 스크롤 하나) |

## 삭제·파괴 동작 (규칙 적용)
- 편성 반 카드 "반 삭제"(저장 전): 빨간 글자 ghost, 확인 창 없이 지우고 5초 되돌리기(화면에서 되살림). 들어 있던 학생은 남은 학생으로.
- 운영 학생 "빼기": 빨간 글자 ghost, 확인 창 대신 즉시 숨김 + 5초 되돌리기(removeTempAssignment를 5초 늦춰 호출). 수업 기록이 있으면 지금처럼 버튼 없음.
- 기간 삭제(되돌릴 수 없음): 제목 줄에서 "기간 수정" 창 아래 왼쪽 빨간 글자 + 확인 창으로 옮김(반 삭제와 같은 규칙). 수업 기록이 있으면 지금처럼 숨김.
- 기간 마감: 확인 창 유지. 시험 일정 삭제: 수정 창 아래 왼쪽 빨간 글자 + 확인 창(지금 그대로).

## Assumptions
- 이 페이지에 "점수" 일괄 입력은 없다. 일괄 입력은 빠진 학교의 시험일·교재·범위를 넣는 BulkModal뿐(점수는 반 상세 테스트 탭, 범위 밖).
- 편성 구획은 단계 잠금 없이 앵커 이동(순서 없이 오가며 고침). 지금 보는 구획을 이동 줄에서 강조.
- 편성 저장(applyExamGroups 한 번), 이름이 같은 반 합치기, 학생별 복귀일 계산은 지금 그대로. 편성 오류는 해당 반 카드를 펼치고 칸으로 이동.
- 저장 안 한 변경: 편성 화면·한 번에 입력 창 모두 떠날 때 ConfirmDialog(BulkModal은 지금 없음 → 추가).
- 긴 설명 문장(기간 탭, 편성 안내, 휴강 설명)은 접는 도움말 한 줄로.
- 이동은 이름 링크 하나(기간 표 줄 onClick 없앰). 휴대폰: 표는 카드, 버튼·체크 줄 42px 이상, 구획 이동 줄·반 바로가기 줄은 넘침 표시.
- `src/`·`lib/` 변경 없음.

## Open questions
- 편성 화면: 앵커 구획 이동(한 페이지) vs 단계식(① → ② → ③ 한 화면씩)
- 남은 학생 목록을 학교·학년으로 묶을지, 지금처럼 평평한 표 + 검색만 둘지
- 기간 삭제를 기간 수정 창 안으로 옮길지, 제목 줄 빨간 글자 버튼으로 둘지

# 화면 8: 설정 (v10~)

## Purpose
보고서·PDF에 들어가는 학원 정보·문구·과제 등급 설명을 고치고 한 번에 저장하며, 3월에 한 번 재원생 학년을 올린다.

## Core flow (one)
사이드바 "설정" → 칸을 고침(고친 구획에 "● 변경", 아래 저장 막대에 변경 구획 수) → 설정 저장(Ctrl+S) / 떠나려 하면 ConfirmDialog

## Screens in scope
- `settings` (/settings): 제목 줄(설정 · 부제, 오른쪽 동작 없음) → 학원 정보(학원명·담당 강사명·연락처 한 줄) → 보고서 문구([인사말·맺음말 | 일일 보고서 처음·끝 미리보기]) → 과제 이행 등급 기준(한 줄 안내 + "▸ 등급 계산 방법" 접힘, A~F 칸 6개 한 줄 / 휴대폰 2열) → 새 학년도 준비("저장과 별개 · 바로 적용" + "▸ 자세히" | 학년 올리기…) → 저장 막대(아래 고정: 저장됨 / ● 변경 N곳 · 변경 취소 · 설정 저장)
- `settings-promotion` (학년 올리기 창): 제목 줄(✕) → 인원·되돌릴 수 없음 안내 → 미리보기 표(지금 → 바뀐 후 · 학생 수) → 그대로 두는 학생 → 취소 · "N명 학년 올리기"(아래 고정). 휴대폰은 화면 전체
- 공통 틀과 화면 1~7은 v9 그대로

## 긴 안내 문구
- 과제 등급 기준: "항목 등급 A 100, B 89 … 평균 내 A 90점 이상 …" → 한 줄 + "▸ 등급 계산 방법" 펼침
- 새 학년도 준비: "3월에 한 번 … 미리 보기에서 확인한 뒤 적용합니다" → 한 줄 + "▸ 자세히"
- 학원 정보·보고서 문구 안내는 이미 한 줄이라 그대로

## Assumptions
- 저장은 지금처럼 전체 한 번(구획별 저장 아님). 저장 막대에 "변경 취소"(마지막 저장 값으로) 추가, Ctrl+S 저장.
- 저장 안 한 변경: 앱 안 링크는 ConfirmDialog, 새로고침·닫기는 beforeunload(화면 1·7과 같음).
- 구획 4개라 구획 이동 줄은 두지 않음. 휴대폰: 칸 세로 쌓기, 입력칸·버튼 42px 이상, 가로 넘침 없음.
- 보고서 미리보기는 새 제안(처음·끝 문구만 이어 붙임, 서버 호출 없음). 휴대폰은 "▸ 미리보기" 접힘.
- 빈 칸은 기본값을 흐린 예시 글자(placeholder)로 보여 줌.
- 학년 올리기는 설정 저장과 별개, 창 자체가 확인 단계(별도 확인 창 없음). 이 화면에 삭제 동작은 없음.
- `src/`·`lib/` 변경 없음.
