# 학생 관리 시스템

강사용 학생 관리 웹앱입니다. 수업 기록, 성적 통계, 상담 일지를 관리합니다. 브라우저는 **Next.js API**만 호출하고, 데이터는 **Postgres**에 둡니다.

```text
브라우저 (Next.js React 화면)
        ↓  /api/*
Next.js (검증 · 통계 · 보고서)
        ↓  SQL
Postgres (Students, Classes, Lessons, ...)
```

Google Apps Script / 시트 왕복은 사용하지 않습니다.

## 로컬 실행

Node.js 22+ 와 `.env.local`이 필요합니다.

```bash
cp .env.example .env.local
# DATABASE_URL, AUTH_SECRET, LMS_PASSWORD 를 채웁니다.

npm test
npm run dev
```

브라우저에서 `http://127.0.0.1:8787` 로 접속합니다. 로그인 비밀번호는 `LMS_PASSWORD`입니다. 샘플 데이터가 필요하면 `npm run seed` 를 한 번 실행하세요.

Postgres 없이 화면만 확인하려면 개발 전용 파일 저장소를 씁니다(운영 빌드에서는 꺼집니다). 처음 실행할 때 데모 반·학생·수업 기록이 자동으로 들어갑니다.

```bash
LMS_STORE=file AUTH_SECRET=dev LMS_PASSWORD=dev npm run dev   # 데이터: dev-server/data.json
```

## 화면 구성

| 메뉴 | 내용 |
|---|---|
| 오늘 | 주간 띠(날짜별 할 일 수), 수업 카드, 할 일(상담 후속 포함, 직접 추가·수정·삭제: 날짜·종류·학생·반), D-7 학교 시험, 주의 학생, 이번 주 숙제 확인, 보강 추가 · 반을 누르면 **수업 기록**(반 공통 → 지난 숙제 확인 → 오늘 숙제 → 학생별, 한 번에 저장) |
| 학생 | 목록(필터·검색·경고 배지·다음 시험·**미배정** 필터) · 상세 탭: 개요, 출결 달력, 수업 기록, 숙제, 성적, 상담(후속 조치), 보고서, 반 이력 · 수업 기록 표에서 그 학생의 출결만 다시 고침(점수·숙제는 유지) · 성적 평균은 100점 환산 · 전체 상담 기록 |
| 반 | 정규 반 목록(시험대비 반은 시험 탭에서 편성·관리하고, 시험대비 반 상세의 상단 경로는 그 시험대비 기간으로 돌아감) · 상세 탭: 개요, 진도 기록, 숙제 기록, 테스트 기록, 강의 계획(월→주→일, AI 제안·확정), 학생, 통계 · 요일별 수업 시간(숫자 입력: 1800 → 18:00) · 교재(바꾸면 이전 교재 기간이 남음)·단원 목록 · 하루 휴강 · 학생 반 변경(이동·빼기·잘못 넣은 배정 삭제, 여러 명 한 번에 이동) · 제목 옆 반 선택으로 다른 반 바로 열기 · 통계 탭의 학생별 월 평균은 100점 환산, 6개월 추이는 만점이 같은 원점수 |
| 시험 | 학교별 수학 시험 일정·범위 · 시험대비 기간(등록하면 바로 편성 화면 — 학교별 자동 그룹 없이 시험대비 반을 직접 만들고 재원생 목록에서 검색·다중 선택으로 학생을 골라 넣음, 정규 반이 없는 재원생도 편성 가능, 원래 반 휴강, 학생별 복귀일은 그 학교 시험 기간의 마지막 날(반 기간과 겹칠 때, 없으면 반 종료일)이 기본이고 다음 날 원래 반으로 복귀, 기간 안에서 반 이름은 서로 달라야 하고 이미 있는 시험대비 반에는 그 반 카드로 학생 추가) · 기간 상세의 시험대비 반 카드에서 `수업 기록하기`·`일일 리포트`로 바로 이동(기간 마감 후에도 수업 기록이 있는 날은 일일 리포트에서 그 반 선택 가능) |
| 보고서 | 일간(반·날짜별 미리보기·복사) · 월간(상태표, 기본/AI 일괄 생성, 편집·확정·PDF) |
| 설정 | 학원 정보, 보고서 문구, 과제 등급 기준, 새 학년도 학년 올리기 |

화면 위 검색창(`Ctrl+K` 또는 `/`)에서 학생 이름·학교·전화 뒷자리, 반 이름으로 바로 이동합니다.

상단의 **AI 비서** 버튼(`Ctrl+J`)은 어느 화면에서든 오른쪽 채팅 패널을 엽니다. 아래 [AI 비서](#ai-비서) 절을 보세요.

## 데이터베이스

테이블은 `lms.kv` 한 곳에 JSON으로 저장합니다. 학원 규모에서는 이 구조가 단순하고, Apps Script 시트 읽기보다 훨씬 빠릅니다.

- `Students`, `Classes`, `StudentClasses`, `Lessons`, `ClassPlans`, `PlanDrafts`, `HomeworkItems`, `HomeworkChecks`, `MonthlyReports`, `Settings`, `_Meta`
- 수업 기록 고유 키는 `lesson_date + student_id + class_id`
- 강의 계획(`ClassPlans`) 고유 키는 `class_id + period_type(일간|주간|월간) + period_key`. 확정된 계획만 들어갑니다. 초안(학생 제안 포함)은 `PlanDrafts`에 따로 두고, 30일 지난 적용·폐기 초안은 지웁니다. 새 계획은 월간·일간만 만들고, 주간은 그 주 일간에서 요약합니다
- 반의 교재·단원 목록은 `Classes.curriculum`, 하루 휴강은 `Classes.cancel_dates`
- 숙제 항목(`HomeworkItems`)은 반·수업일별 칸이며, `student_id`가 비면 반 공통·있으면 그 학생 개인 숙제입니다. 이행 등급(`HomeworkChecks.status`, A–F)은 `item_id + student_id`. 학생 기록의 `homework_replace_class`가 켜지면 그 학생은 공통 숙제 대신 개인 숙제만 배정·채점됩니다.
- 반 단위 수업(`ClassSessions`)은 `lesson_date + class_id` 한 건: 진도·수업 내용·테스트 정보(이름·만점·난이도·범위)·반 공지. 저장하면 학생별 수업 기록에도 진도·만점·시험 범위·유효 숙제 글이 복사되어 기존 보고서·통계가 그대로 동작합니다. 시험 범위는 그날 학생 기록 전체에 복사되고, 일일 보고서 테스트 줄 아래에 붙습니다. 학생별 `student_notice`(개별 공지)는 피드백(`special_note`)과 별도로 일일 보고서에 붙습니다.
- 반 시간표는 `Classes.schedule`(요일별 시작·종료), `weekday/start_time/end_time`은 호환용 파생값
- 학교 시험(`SchoolExams`), 시험대비 기간(`ExamPeriods`), 임시 배정(`StudentClasses.status = '임시'`, 시작·종료일)
- 데이터 구조 변경은 `_Meta`의 스키마 버전으로 처음 접속할 때 한 번 자동 적용됩니다(다시 실행해도 결과 동일)
- 학생 퇴원·반 종료는 행을 지우지 않고 상태를 바꿉니다
- 기록 없는 반 삭제: 잘못 만든 반은 수업 기록·숙제 체크가 없고 시험대비 편성의 원래 반이 아닐 때만 반 상세 `삭제`로 지웁니다(배정·반 기록·숙제 항목·강의 계획·보강도 함께 지우고, 할 일은 반 연결만 비우며, 시험대비 휴강 목록에서도 뺍니다)
- 반 배정(`StudentClasses`): ‘반에서 빼기’는 종료일을 넣어 기록을 남기고, ‘배정 삭제’는 그 반에 수업 기록·숙제 체크가 없을 때만 행을 지웁니다. 두 반을 다니는 학생을 옮길 때는 어느 반에서 옮기는지 정해야 합니다
- **미배정**은 저장하지 않고 계산합니다: 재원생인데 오늘 다니는 반도, 시작 예정인 반도 없는 경우

스키마 SQL은 `supabase/migrations/` 에 있습니다.

## 배포 (Vercel)

1. 이 저장소를 Vercel 프로젝트에 연결합니다.
2. 환경 변수 `DATABASE_URL`, `AUTH_SECRET`, `LMS_PASSWORD`를 넣습니다.
   `DATABASE_URL`은 Supabase **Session pooler**(6543) 주소를 씁니다.
   월간 보고서 **AI 분석**은 OpenRouter를 사용합니다. [openrouter.ai/keys](https://openrouter.ai/keys)에서 발급한 키를 `AI_API_KEY`에 넣습니다. 모델을 지정하지 않으면 `openrouter/free`가 그 요청에 쓸 수 있는 무료 모델 중 하나를 고릅니다. 특정 모델로 고정하려면 `AI_MODEL`을 추가합니다.
3. 함수는 `icn1`(서울)에서 실행되어 서울 Postgres와 가깝습니다.

빈 데이터베이스에서 반과 학생을 바로 등록하면 됩니다. 로컬에서 샘플 화면만 보려면 `npm run seed` 로 데모 3명을 넣을 수 있습니다.

## 보안

- 웹앱은 비밀번호 세션으로 막습니다. 비밀번호는 서버 환경 변수에만 둡니다.
- 브라우저에 데이터베이스 키를 넣지 않습니다. 모든 읽기/쓰기는 서버 API를 통과합니다.
- `/api/[name]`은 `lib/public-api.js` 허용 목록(화면이 실제로 부르는 업무 함수)만 호출합니다. 화면에서 새 함수를 부르면 목록에 추가해야 하며, `tests/public-api.test.js`가 빠진 이름을 잡습니다.
- AI API 키는 서버 환경 변수에만 두며, 월간 보고서 생성 시 수업·성적·상담 요약 JSON이 OpenRouter로 전송됩니다.
- AI 비서는 강사 메시지와 조회 결과(학생 이름, 학교, 출결·성적·숙제·상담 내용 등)를 AI로 보냅니다. `ANTHROPIC_API_KEY`가 있으면 Anthropic으로만, 없으면 OpenRouter를 거쳐 보냅니다. 전화번호는 도구 결과에 넣지 않습니다.
- 강의 계획 AI 제안에는 학생 이름 대신 `S1, S2…` 별칭과 숫자 요약(출석·숙제 완료율·숙제 평균 점수·최근 점수·학습 신호)만 보냅니다. 연락처·메모·상담 내용은 보내지 않습니다.

## 강의 계획

흐름은 하나입니다: **초안 만들기 → 고치기 → 최종 확정**. 반 상세 → `강의 계획` 탭이 한 달을 월 목표 → 주(요약) → 수업일 순서로 보여 주고, 수업일마다 계획과 실제 진도·진행 결과가 나란히 보입니다.

1. **단원 목록 준비**: 반 정보 수정에서 단원을 순서대로 넣고 예상 수업 횟수를 적습니다. 여러 줄 붙여넣기(`단원 / 횟수`)도 됩니다. `지금`으로 지금 나가는 단원을 고르면 그 앞 단원은 끝난 것으로 봅니다. 이름이나 순서를 바꿔도 계획과의 연결은 유지됩니다.
2. **초안 만들기**: 버튼 하나로 이 달의 남은 수업일(휴강·시험대비 제외, 반 보강 포함) 계획 초안을 만듭니다.
   - AI 키가 있으면 AI가 진도, 최근 4주 출석·숙제, 테스트, 다가오는 학교 시험, 학생별 신호를 보고 수업일 계획, 이 달 목표, 학생별 제안(보충 과제·클리닉·상담·보강)과 근거를 씁니다.
   - 키가 없거나 AI가 실패하면 단원 순서대로 나눈 초안을 대신 만들고 이유를 표시합니다.
   - 수업 기록에서 `일부`·`못 함`으로 표시한 단원은 뒤로 밀립니다.
3. **고치기**: 초안의 이 달 목표, 수업일 계획, 학생 제안을 확정 전에 바로 고치고, 넣을지 뺄지 고릅니다. 초안은 확정 전까지 다른 화면에 나오지 않습니다.
4. **최종 확정**: 고른 계획을 저장하고, 고른 학생 제안을 다음 수업일 할 일로 등록합니다.
   - 강사가 고친 계획은 직접 쓴 계획이 되어, 다음 초안에서도 기본으로 유지됩니다.
   - 지난 날과 기록 있는 날은 바뀌지 않습니다.
   - 검토하는 사이 계획이 바뀌면 확정을 막고 다시 비교합니다.

- **하루 휴강**: 수업일 카드나 수업 기록 화면에서 지정하고 언제든 취소합니다. 휴강일은 오늘 화면, 숙제 확인, 진도 기록, 초안 모두에서 빠집니다. 그날 계획은 초안을 다시 만들면 남은 수업일로 다시 나뉩니다. 기록이 있는 날은 휴강할 수 없습니다.
- **수업 기록**: 진도 칸 위에 오늘 계획과 `완료/일부/못 함`이 함께 나옵니다. 고르지 않으면 계획대로 끝낸 것으로 봅니다.

## AI가 쓰이는 곳

AI는 월간 보고서·강의 계획에서는 **초안 글쓰기에만** 씁니다. 계산(수업일, 진도, 휴강, 비교, 검증)은 모두 코드로 하고, AI 결과는 언제나 강사가 확정해야 반영됩니다.

| 화면 | AI에게 주는 것 | AI가 쓰는 것 | 그 다음 |
|---|---|---|---|
| 보고서 → 월간 | 한 학생의 한 달 수업·성적·상담·학습 신호 | 【학습 분석】【피드백】【다음 달 제안】 문단 | 기본 보고서 뒤에 붙음 → 강사가 편집·확정 |
| 반 → 강의 계획 | 단원 진행, 남은 수업일, 4주 출석·숙제, 시험, 학생별 요약(별칭) | 이 달 목표, 수업일 계획, 학생 제안, 근거 | 서버가 날짜·단원·명단으로 검증 → 초안 → 강사가 고치고 확정 |
| 상단 → AI 비서 | 강사 메시지, 대화 이력, 조회 도구 결과(학생 이름 포함) | 답변, 변경 제안(출결·상담·할 일) | 조회는 바로 답변, 변경은 강사가 승인하면 같은 업무 함수로 실행 → 다시 읽어 확인 |

설정은 `AI_API_KEY`(필수), `AI_MODEL`, `AI_BASE_URL` 하나로 모든 AI 기능이 함께 씁니다(`lib/ai-client.js`). AI 비서는 도구 호출(tool calling)을 쓰므로 도구 호출을 지원하는 모델이 필요합니다. 연결 방식은 둘입니다.

- **권장: Anthropic API 직접** — `ANTHROPIC_API_KEY`([console.anthropic.com](https://console.anthropic.com)에서 발급)를 넣으면 AI 비서는 공식 SDK(`@anthropic-ai/sdk`)로 **Claude Haiku 5.5**(`claude-haiku-5-5`)를 부릅니다. 학생 데이터가 중간 업체를 거치지 않고, 반복되는 도구 목록·지시문은 프롬프트 캐싱으로 싸게 재사용합니다. 다른 Claude 모델은 `AGENT_MODEL`에 Anthropic 모델 ID(예: `claude-sonnet-5-5`)로 넣습니다. 이전 안내대로 `anthropic/claude-haiku-5.5` 같은 OpenRouter 형식이 남아 있어도 자동으로 바꿔 씁니다.
- **OpenRouter** — `ANTHROPIC_API_KEY`가 없으면 지금처럼 `AI_API_KEY`로 OpenRouter를 거칩니다. `AGENT_MODEL`에 넣으면 AI 비서만 그 모델을 쓰고(비우면 `AI_MODEL`), 기본값 `openrouter/free`는 도구 호출을 못 하거나 불안정할 수 있습니다.

월간 보고서·강의 계획은 연결 방식과 관계없이 OpenRouter(`AI_API_KEY`, `AI_MODEL`)를 씁니다. 학생 식별이나 여러 단계 지시를 Haiku가 자주 틀리면 Claude Sonnet 5.5로 올립니다.

`temperature`(답변의 다양성)는 기능마다 정해 두고, 보낼지는 `lib/ai-client.js`의 `temperatureFor`가 모델 ID로 정합니다. 최신 Claude 모델은 기본값이 아닌 값을 거부하므로 Claude 모델(ID에 `claude`가 있거나 `anthropic/`으로 시작)에는 어느 기능도 보내지 않습니다. 그래서 `AI_MODEL`·`AGENT_MODEL` 어디에 Claude를 넣어도 됩니다.

| 기능 | 모델 설정 | Claude 외 모델 | Claude 모델 |
|---|---|---|---|
| 월간 보고서 AI 분석 | `AI_MODEL` | 0.4 | 보내지 않음 |
| 강의 계획 AI 초안 | `AI_MODEL` | 0.3 | 보내지 않음 |
| AI 비서 (OpenRouter 연결 시) | `AGENT_MODEL`(비면 `AI_MODEL`) | 0.2 | 보내지 않음 |

Anthropic API로 직접 부를 때는 temperature를 보내지 않고, 답변 깊이는 `effort: low`로 정합니다.

## AI 비서

강사가 채팅으로 지시하면 AI가 기존 업무 함수를 도구로 불러 처리합니다. 음성 입력은 아직 없습니다.

- **조회는 바로**: 학생 찾기, 학생 개요, 출결 달력, 수업 기록, 성적, 숙제 이행, 상담 기록, 오늘 현황, 반 목록·명단.
- **변경은 승인 후**: 출결 변경(이미 기록된 수업만), 상담 기록 추가(후속 할 일 포함), 할 일 상태 변경. AI는 바꾸지 않고 **변경 제안 카드**를 만들고, `승인하고 반영`을 누르면 그때 수동 화면과 같은 서비스 함수(`updateLessonAttendance`, `saveCounselingNote`, `updateTaskStatus`)로 실행합니다.
- **검증**: 실행 직후 저장된 값을 다시 읽어 `확인됨`/`불일치`를 표시합니다. 하나라도 실패하면 그 제안의 변경을 모두 되돌리고 실패 사유를 남깁니다. 같은 제안을 두 번 승인해도 한 번만 실행됩니다.
- **한꺼번에 처리**: AI 비서 패널의 **승인 대기** 목록에서 여러 제안(Claude 커넥터에서 온 것 포함)을 골라 한 번에 반영하거나 거절할 수 있습니다(한 번에 100건까지). 반영은 오래된 제안부터 하나씩 따로 실행하므로, 중간에 하나가 실패해도 그 제안만 되돌리고 나머지는 반영됩니다.
- **안 하는 일**: 성적 입력, 진도 수정, 문자 발송은 아직 도구가 없어 해당 화면을 안내합니다. AI가 SQL이나 테이블을 직접 건드리지 않습니다.
- **사용량 제한**: AI 비용이 늘지 않도록 한 시간에 `AGENT_RATE_LIMIT_PER_HOUR`번(기본 60, `0`이면 제한 없음)까지만 대화를 처리합니다. 횟수는 DB(`AgentUsage`)에 남겨 서버 인스턴스가 여럿이어도 함께 셉니다. 넘으면 429와 함께 몇 분 뒤에 다시 쓸 수 있는지 알려 줍니다. 승인(`/api/agent/apply`)은 AI를 부르지 않고 제안마다 한 번만 실행되므로 세지 않습니다.
- **기록**: 대화(`AgentConversations`, `AgentMessages`)와 제안(`AgentProposals`: 변경 전/후, 상태, 검증 결과, 실행 시각)은 따로 저장합니다. 대화는 참고용이고, 학생 데이터의 기준은 언제나 업무 테이블입니다. 90일 동안 이어지지 않은 대화는 새 대화를 저장할 때 메시지와 함께 지웁니다(승인 대기 제안이 있는 대화는 남김). 제안 기록은 지우지 않습니다.
- 구조: `components/shell/AgentPanel.js` → `/api/agent`(`lib/agent.js` 도구 호출 루프, AI 대기 중에는 DB 잠금을 잡지 않음 · 연결은 AI 제공자 adapter `lib/agent-anthropic.js`(Anthropic) 또는 `lib/agent-openai.js`(OpenRouter)) · 승인은 `/api/agent/apply`, 거절은 `/api/agent/reject`(한 건 `proposal_id`, 여러 건 `proposal_ids`) · 도구 목록 `lib/agent-tools.js` · 제안 만들기·반영·거절 `lib/proposals.js`(대화·MCP·승인 화면 모두 이것만 부름), 제안 저장·검증 `src/07_Agent.js`.

## Claude 커넥터

claude.ai에서 이 앱을 **커스텀 커넥터**(원격 MCP)로 연결하면, Claude 대화 안에서 AI 비서와 같은 도구로 학생 정보를 조회하고 바꿀 수 있습니다. 앱 쪽 AI 키는 필요 없습니다.

1. Vercel에 배포합니다(위 `배포` 참고). claude.ai는 인터넷에서 접근할 수 있는 HTTPS 주소만 연결하므로, 로컬 `127.0.0.1`로는 연결되지 않습니다.
2. 앱의 설정 → **Claude 커넥터** 카드에서 쓰기 권한을 고르고 저장한 뒤, 커넥터 URL을 복사합니다.
   - **조회만**(기본): Claude는 읽기 도구만 봅니다. 출결·상담·할 일은 바꿀 수 없습니다.
   - **승인 대기 제안**: Claude가 요청한 변경은 `[Claude 커넥터]` 대화로 AI 비서 패널의 승인 대기에 올라가고, 강사가 승인해야 저장됩니다. 쌓인 제안은 승인 대기 목록에서 골라 한 번에 반영하거나 거절할 수 있습니다.
   - **승인과 거절은 앱에서만** 합니다. Claude에는 승인·거절 도구가 없고, 코드(`lib/proposals.js`)도 로그인한 앱 화면이 아닌 호출자의 승인·거절을 거부합니다([ADR-0002](docs/adr/0002-approval-only-in-app.md)). Claude는 `list_pending_proposals`로 이 커넥터가 올린 대기 제안을 보여 줄 수만 있습니다(앱의 AI 비서 대화에서 올린 제안은 보이지 않음. `AgentProposals.source`, 이 값이 없는 예전 제안은 `[Claude 커넥터]` 대화 제목으로 구분).
   - Claude가 바로 저장하는 경로는 없습니다. 추가·수정·삭제 모두 승인 대기를 거칩니다. 예전에 저장된 `direct`, `claude_approve`(승인 대기 + Claude에서 승인, 없어짐) 값은 DB를 고치지 않아도 **승인 대기 제안**으로 처리되고, 설정을 다음에 저장할 때 `proposal`로 바뀝니다.
   - 모드는 요청마다 설정에서 읽으므로, 바꾸면 다시 연결하지 않아도 바로 반영됩니다.
   - 도구 호출은 한 시간에 `MCP_RATE_LIMIT_PER_HOUR`번(기본 300, `0`이면 제한 없음)까지입니다. AI 비서 대화 횟수와 따로 `AgentUsage`에 셉니다.
3. claude.ai의 설정 → 커넥터 → **커스텀 커넥터 추가**에 `https://<도메인>/api/mcp`를 넣습니다.
4. 로그인 창이 열리면 `LMS_PASSWORD`로 로그인하고 **허용**을 누릅니다.

- **연결 목록**: 설정 카드의 `연결된 커넥터`에 동의 화면에서 허용한 연결마다 이름, 허용한 때, 마지막 갱신이 나옵니다(`OAuthGrants`). `끊기`는 그 연결의 토큰만 무효로 합니다. 이 목록이 생기기 전에 연결한 커넥터는 다음 토큰 갱신(1시간 안) 뒤에 나타납니다.
- **연결 끊기**: 설정 카드의 `연결 끊기`는 지금까지 Claude에 발급된 접근·갱신 토큰을 모두 무효로 만듭니다(설정 `mcp_token_version`을 올림). 다시 쓰려면 claude.ai에서 다시 연결합니다.
- **재사용 감지**: 이미 쓴 인가 코드나 갱신 토큰이 다시 오면 그 연결을 끊습니다. Claude에서 다시 연결해야 합니다.
- **동의 화면**: 직접 시작한 연결이 아니면 거부하라는 경고가 나옵니다. 클라이언트 등록(`/api/oauth/register`)은 15분에 IP당 10번, 전체 30번까지입니다(`lms.login_attempts`의 `register:` 칸).
- **도구**: 조회는 학생 찾기, 학생 개요, 출결 달력, 수업 기록, 성적, 숙제 이행, 상담 기록, 하루 현황, 반 목록·명단. 변경(조회만이 아닐 때)은 출결 변경, 상담 기록 추가, 할 일 상태 변경. 읽기 도구는 읽기 전용, 쓰기 도구는 되돌릴 수 없는 작업으로 표시되어 Claude가 실행 전에 확인을 받습니다.
- **인증**: OAuth 2.1(PKCE S256, 동적 클라이언트 등록). 토큰은 `AUTH_SECRET`에서 용도(로그인 쿠키, 클라이언트 ID, 인가 코드, 토큰)마다 HKDF로 만든 키로 서명하며 따로 저장하지 않습니다(`lib/signing.js`, 예전에 `AUTH_SECRET` 자체로 서명한 값도 만료 때까지 통과). 인가 코드와 갱신 토큰은 한 번만 쓸 수 있도록 쓴 것의 ID만 만료 때까지 DB(`OAuthJti`)에 남기고, 갱신할 때마다 새 갱신 토큰을 줍니다. 인가 코드 5분, 액세스 토큰 1시간, 갱신 토큰 30일. 돌려보낼 주소는 claude.ai·claude.com의 커넥터 콜백만 허용합니다.
- 구조: `/api/mcp`(`app/api/mcp/route.js` → `lib/mcp-server.js`, 무상태 Streamable HTTP) · OAuth `lib/oauth.js`, `/.well-known/oauth-*`, `/api/oauth/register`, `/api/oauth/token`, 동의 화면 `/oauth/authorize`.

## 숙제 체크리스트

- **수업 기록**: 오늘 내줄 반 공통 숙제를 칸별로 입력하고, 학생별 기록에서 개인 숙제를 추가하거나(또는 반 숙제 제외 후 개인만) 낼 수 있습니다. 직전 수업 숙제는 학생별 유효 항목마다 A–F로 확인합니다(확인 전이면 모두 A로 시작해 낮은 항목만 바꿉니다).
- **개별 공지**: 학생별 기록의 개별 공지 칸은 피드백과 분리되며, 일일 보고서에 `개별 공지`로 표시됩니다.
- **과제 이행률**: 그 학생의 항목 등급(A 100, B 89, C 79, D 69, E 59, F 50)을 평균 내 A(90+) / B(80+) / C(70+) / D(60+) / E(51+) / F(50 이하)로 계산합니다. 아직 고르지 않은 항목은 평균에서 빠집니다.
- **숙제 완료**: 항목 등급이 A일 때만 완료입니다(예전 값 `완료`는 A). B–F는 미완료입니다. 숙제 완료율은 확인한 항목 중 A의 비율이고, 그 옆에 등급 점수 평균인 **숙제 평균 점수**를 함께 보여 줍니다. 미완료 목록·학생 배지·이번 주 숙제 확인의 미완료 학생 수는 A 기준을 씁니다.
- **이번 주 숙제 확인**: 오늘 화면에서 각 수업일의 직전 수업 숙제 완료 상황을 봅니다. 반 상세 `숙제 기록` 탭에서 학생별 완료 표를 봅니다.
- 한 시험의 반 평균과 일일 보고서는 원점수입니다. 만점이 다르면 그날 반 평균은 비웁니다. 학생 개인 화면과 월간 보고서의 시험 평균은 만점이 달라도 100점 환산입니다.

## 월간 보고서 (AI · PDF)

- **기본 보고서**: 기존처럼 통계 템플릿으로 문장을 만듭니다. 보고서 → 월간에서 반 단위로 일괄 생성할 수 있습니다(확정본은 건드리지 않음).
- **확정본 보호**: 확정된 보고서는 내용을 바꿀 수 없습니다. 편집 창의 **확정 취소**로 임시로 되돌린 뒤 고칩니다. 일괄 생성은 확정본을 건너뛰고, AI 비서·Claude 커넥터는 확정본을 고치거나 확정 취소할 수 없습니다. 규칙은 서비스 `saveMonthlyReport`(`LMS.assertMonthlyReportWritable`) 한 곳에 있습니다.
- **AI 분석 포함**: 보고서 → 월간에서 학생별 또는 선택한 학생 일괄로(2명씩) 생성하면, 같은 달 수업·상담·학습 신호를 바탕으로 `【학습 분석】`, `【학생 피드백·관찰】`, `【다음 달 지도 제안】` 구간을 추가합니다.
- **PDF 저장**: 보고서 편집 창의 **PDF 저장**으로 다운로드합니다 (한글 폰트는 서버에서 자동 로드하거나 `public/fonts/`에 OTF를 둘 수 있습니다).
